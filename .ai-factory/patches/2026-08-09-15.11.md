# Align consumers with renamed OpenAPI operations

**Date:** 2026-08-09 15:11
**Files:** `orval.invalidation.ts`, `src/features/remind/manage-reminds/lib/use-create-remind.ts`, `src/features/note/manage-note/lib/use-personal-note.ts`, `src/widgets/notes-overview/lib/hooks/use-notes-mutations.ts`
**Severity:** medium

## Problem

After renaming instrument and strategy note operations plus the instrument
reminder creation operation in `swagger.yaml`, their generated hook exports no
longer matched the imports and invalidation configuration used by the app.

## Root Cause

Orval derives function and hook names from `operationId`. The application and
the `mutationInvalidates` source still referred to the former ambiguous names.

## Solution

Updated all affected hook imports and the Orval mutation/query mappings to use
the new operation-specific names. The reminder flow keeps its existing local
cache update and calls the current generated hook without unsupported options.

## Prevention

- After changing an OpenAPI `operationId`, search application code and Orval
  overrides for the previous generated symbol names.
- Run the full project check after generation to catch stale imports and hook
  option contracts.
