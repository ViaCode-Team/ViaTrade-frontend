# Show a clear reminder-limit error after failed creation

**Date:** 2026-08-15 19:44
**Files:** `src/features/remind/create-remind/lib/reminder-limit-error.ts`, `src/features/remind/create-remind/lib/use-create-remind.ts`, `src/features/remind/create-remind/ui/create-remind-form.tsx`
**Severity:** medium

## Problem

Creating a reminder could fail with `422` and `code = reminder_limit_exceeded`, but the form did not explain the failure or how the user could continue.

## Root Cause

The create-reminder mutation only handled success. Expected business errors from the API were not classified locally, so the specific limit response was not rendered in the form.

## Solution

Added a focused mapper that recognizes only the `422` `reminder_limit_exceeded` Problem Details response. The creation hook keeps the resulting message in local state, and the form displays a persistent warning without closing the modal. The message tells the user to remove unneeded reminders before trying again.

## Prevention

- Treat expected API business errors as local form feedback instead of letting them disappear into a generic boundary.
- Match both HTTP status and API `code` before showing a domain-specific message.
- Verify creation flows against API limit responses when a backend environment is available.
