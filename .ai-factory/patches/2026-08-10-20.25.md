# Represent unbounded profit factor as an omitted API field

**Date:** 2026-08-10 20:25
**Files:** `Domain/Services/TradeStatisticsCalcService.cs`, `WinrateTradeStatisticDto.cs`, `WinrateTradeStatisticResponse.cs`, `swagger.yaml`, `src/pages/statistics/model/statistics.ts`
**Severity:** high

## Problem

`GET /api/v1/trades/statistics` returned HTTP 400 for users with profitable
closed trades but no losses.

## Root Cause

The server calculated an infinite profit factor and attempted to serialize
`float.PositiveInfinity`, which is not a valid JSON number. The exception
middleware mapped the resulting `ArgumentException` to HTTP 400.

## Solution

Represent an unbounded profit factor as an omitted optional response property.
The frontend displays an absent value as `∞` and the generated OpenAPI type is
optional.

## Prevention

- Do not expose `NaN` or infinity as JSON numeric values.
- Model non-finite financial metrics explicitly in the API contract.
- Verify serialization-sensitive statistic edge cases after changing API types.
