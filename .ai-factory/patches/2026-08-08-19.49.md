# Prevent Windows pre-commit command-length failures

**Date:** 2026-08-08 19:49
**Files:** .husky/pre-commit, docs/GETTING_STARTED.md, docs/GETTING_STARTED_RU.md
**Severity:** low

## Problem

Committing 174 staged files failed in the pre-commit hook because Prettier
received a command line that exceeded the Windows limit.

## Root Cause

`lint-staged` was invoked without an explicit maximum argument length. Its
platform default did not split this repository's staged file list into small
enough command chunks for the Windows command shell.

## Solution

Configured the Husky pre-commit hook to run `lint-staged` with
`--max-arg-length 7000`. Lint-staged now splits the file list before invoking
Prettier. Added the Windows-specific behavior to both getting-started guides.

## Prevention

- Keep an explicit conservative argument-length limit for Windows hooks.
- Validate hooks with a large staged set when changing lint-staged behavior.
- Treat command-line length errors as task chunking configuration issues.
