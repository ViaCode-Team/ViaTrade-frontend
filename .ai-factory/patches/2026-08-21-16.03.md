# Merge single-use create-trade-from-signal feature into its consumer widget

**Date:** 2026-08-21 16:03
**Files:** `src/features/trade/create-trade-from-signal/*`, `src/widgets/signal-history-table/*`
**Severity:** low

## Problem

`npm run arch` failed with `fsd/insignificant-slice`: the
`features/trade/create-trade-from-signal` slice had only one consumer,
`widgets/signal-history-table`.

## Root Cause

The create-trade flow was extracted as a feature before its reuse was
established. Its only consumer is the signal history table, so its separate
FSD boundary did not represent a reusable interaction.

## Solution

Moved the create-trade-from-signal UI and model into
`widgets/signal-history-table` and changed the table view to use a local
component import. Removed the now-empty feature slice without changing the
user flow or mutation behavior.

## Prevention

- Create a feature slice only after a user interaction has multiple real consumers.
- Keep a single-consumer interaction with the consuming page or established widget.
- Run `npm run arch` after introducing or extracting FSD slices.
