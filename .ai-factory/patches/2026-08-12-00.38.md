# Strategy subscription terminology and display names

**Date:** 2026-08-12 00:38
**Files:** src/entities/signal/model/signal.ts, src/pages/landing/ui/example-signals.tsx, src/pages/strategies/ui/strategies-summary.tsx, src/widgets/strategies-overview/, src/widgets/stock-linked-strategies/, src/widgets/notes-overview/model/api-notes.ts
**Severity:** medium

## Problem

The frontend still used active/inactive strategy terminology and displayed the technical strategy name in signals after the API changed to subscription terminology and added display names.

## Root Cause

The generated API contract added `displayName` to signal and brief strategy responses, and renamed strategy statistic fields to subscribed/unsubscribed counts. Existing client models and filter values had not been updated to reflect those contract changes.

## Solution

Mapped signal `strategyName` and `displayName` to separate client fields, using the former for URLs and the latter in the UI. Updated strategy statistics, filter values, counters, labels, and data attributes to use subscribed/unsubscribed terminology.

## Prevention

- Review every generated API diff for added display fields and renamed state fields.
- Keep technical URL identifiers separate from user-facing labels in client models.
- Update type names, persisted filter values, and UI labels together when a domain term changes.
