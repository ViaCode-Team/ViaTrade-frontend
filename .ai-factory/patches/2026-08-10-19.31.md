# Adapt generated clients to renamed session and strategy operations

**Date:** 2026-08-10 19:31
**Files:** `orval.invalidation.ts`, `src/entities/session/api/refresh-interceptor.ts`, `src/entities/strategy/model/use-toggle-user-strategy.ts`
**Severity:** high

## Problem

The refreshed OpenAPI specification renamed the session-token endpoint and
replaced separate strategy activation/deactivation operations with
`UpdateStrategy`. Generated exports used by the frontend no longer existed,
causing TypeScript errors and blocking the build.

## Root Cause

The Orval invalidation configuration and the handwritten adapters still
referenced the old operation IDs. The generated `UpdateStrategy` mutation
therefore lacked the cache invalidation that its predecessor operations had.

## Solution

Updated the auth refresh interceptor to use `CreateCurrentSessionTokens`.
Changed the strategy toggle adapter to call `useUpdateStrategy` with the
required `{ isActive }` request body. Updated Orval mutation invalidation
rules for the renamed operations and regenerated API clients.

## Prevention

- After an OpenAPI operation rename, update Orval invalidation rules together
  with handwritten API adapters.
- Run API generation and the full project check before accepting the contract
  update.
- Confirm that replacement mutations preserve the previous query invalidation
  behavior.
