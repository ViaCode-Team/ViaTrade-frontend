# Apply the hold-signal filter before pagination

**Date:** 2026-08-10 23:58
**Files:** `Application/Trades/Models/SignalHistoryFilter.cs`, `Application/Trades/SignalQueryService.cs`, `src/widgets/signal-history-table/lib/use-history-table.ts`, `swagger.yaml`
**Severity:** medium

## Problem

Hiding hold signals in the history table could leave visible pages empty.

## Root Cause

The frontend filtered `HOLD` rows only after the API had already paginated the
complete signal history. Page counts therefore included rows that were then
removed from the rendered list.

## Solution

Added the `excludeHold` query parameter. The server now removes hold signals
before it calculates the paged result, and the history table sends the
parameter from its default-enabled toggle.

## Prevention

- Apply collection filters before pagination whenever filtered rows affect the
  visible list.
- Include filter state in the request so response totals and page counts match
  rendered data.
- Regenerate OpenAPI types after adding a query parameter.
