# Correct strategy bindings, trade prices, and activation cache updates

**Date:** 2026-08-09 00:07
**Files:** `src/features/strategy/bind-stock/model/use-strategy-linked-stock-ids.ts`, `src/features/strategy/bind-stock/ui/strategy-stock-binding.tsx`, `src/entities/trade/ui/trade-form/trade-form.tsx`, `src/entities/trade/lib/map-trade-form.ts`, `src/widgets/header/ui/add-trade-form/add-trade-form.tsx`, `src/pages/trades/ui/close-trade/close-trade-form/close-trade-form.tsx`, `src/entities/strategy/model/use-toggle-user-strategy.ts`, `orval.invalidation.ts`
**Severity:** critical

## Problem

The strategy-to-stock editor reused the catalogue page number for the unrelated
linked-stock result set, so association checkboxes and mutations were incorrect.
Trade forms accepted zero prices despite requiring positive prices. Activating or
deactivating a strategy left the stock-linked strategy list stale.

## Root Cause

The linked-stock endpoint is independently paginated and has a maximum page size
of 100, so its page number cannot be paired with catalogue pagination. UI-only
validation allowed the boundary value zero and request mapping trusted it. The
activation mutation invalidated strategy queries but omitted instrument strategy
list queries.

## Solution

The binding container now aggregates every linked-stock page into one cached list
of IDs. Trade forms start with an empty entry price, reject non-positive prices,
and the request mapper revalidates values. Activation invalidates the affected
instrument strategy-list cache now, while the Orval invalidation source is updated
for future client generation.

## Prevention

- Never align independent paginated API results by page number.
- Validate financial boundaries in both UI and request mapping layers.
- Include every consumed query family in mutation invalidation rules.
- Add regression coverage for multi-page bindings, zero prices, and stale linked lists.
